# AGENTS.md

## Назначение проекта

Учебное веб-приложение на SvelteKit для решения задачи № 6:

> Запросить число и вывести на экран максимальный и минимальный чётные делители введённого числа.

Результат — одна страница с формой ввода, вычислением и понятным выводом результата. Не добавляй функции, которые не нужны для решения задачи.

Общение с пользователем, интерфейс, README и сообщения коммитов — на русском языке. Идентификаторы в коде — на английском.

## Контракт задачи

Принятая трактовка: ищем **положительные чётные делители** введённого целого числа. Для отрицательного числа рассматриваем его модуль. Объясни эту трактовку в интерфейсе и README.

### Ввод

- Принимай десятичную запись целого числа с необязательным знаком `+` или `-`. Пробелы по краям удаляй; ведущие нули допускаются.
- Проверяй всю строку до преобразования в число. Пустая строка, дроби, экспоненциальная запись, шестнадцатеричная запись и посторонние символы недопустимы.
- Не используй `parseInt` как валидацию ввода: строка `12abc` должна приводить к ошибке, а не к вычислению для `12`.
- После преобразования проверяй `Number.isSafeInteger`. Значения вне безопасного целочисленного диапазона отклоняй с понятным сообщением.
- Ноль, включая `-0`, отклоняй: максимального положительного чётного делителя у него нет.
- Не округляй, не обрезай и не исправляй некорректный ввод молча.

### Вычисление

Для корректного ненулевого числа используй `m = Math.abs(n)`:

- Если `m` нечётное, результат: «Чётных делителей нет».
- Если `m` чётное, минимальный положительный чётный делитель равен `2`, максимальный — `m`.
- Для `2` и `-2` оба результата равны `2`.

Не перебирай делители без необходимости: для этой трактовки достаточно проверки чётности. Если предоставленная методичка отдельно требует цикл или конкретный алгоритм, выполни это требование и отрази выбранный алгоритм в README.

Отличай отсутствие чётных делителей от ошибки ввода. Не используй `0`, `NaN` или `Infinity` как условное обозначение отсутствующего результата.

## Правила Svelte

- Используй `<script lang="ts">` и типизированные функции; не скрывай проблемы типов через `any` и необоснованные приведения.
- Для локального реактивного состояния используй `$state`; для действительно производных значений — `$derived`.
- Не применяй `$effect` для обычного вычисления результата или синхронизации дублирующего состояния.
- Используй обработчики событий Svelte 5, например `onsubmit`. Обрабатывай отправку формы без перезагрузки страницы.
- Не отключай SSR всего приложения ради этой задачи. Не обращайся к `window` и `document` при серверном выполнении.
- Выводи пользовательские данные как текст, без `{@html}`.
- Следуй имеющимся настройкам форматирования и стилям проекта. Не подавляй предупреждения компилятора и доступности вместо исправления причин.

## Интерфейс

На странице должны быть название задачи, краткое условие, подписанное поле ввода, кнопка «Вычислить» и область результата.

- Отправка формы работает и кнопкой, и клавишей Enter.
- Результат содержит явно подписанные максимальный и минимальный чётные делители.
- Отсутствие делителей показывай как обычный результат, а не как ошибку приложения.
- Ошибку ввода показывай рядом с полем и связывай с ним средствами доступности. Динамический результат должен быть доступен скринридеру.
- При изменении ввода сбрасывай прежний результат и прежнюю ошибку, чтобы они не выглядели относящимися к новому значению.
- Обеспечь управление с клавиатуры, видимый фокус и отсутствие горизонтального переполнения на узком экране.
- Не добавляй искусственные задержки, загрузочные состояния, модальные окна и анимации, не нужные для решения.

## Проверки

Покрой валидацию и вычисления модульными тестами. Используй существующий тестовый инструмент; если его нет, добавь минимальную настройку Vitest.

Обязательные примеры:

| Ввод | Ожидаемый результат |
| --- | --- |
| `2`, `-2` | Минимальный `2`, максимальный `2` |
| `6` | Минимальный `2`, максимальный `6` |
| `12`, `-12` | Минимальный `2`, максимальный `12` |
| `100` | Минимальный `2`, максимальный `100` |
| `1`, `7`, `-7` | Чётных делителей нет |
| `0`, `-0` | Ошибка: максимального положительного чётного делителя нет |
| `  +12  `, `0012` | Минимальный `2`, максимальный `12` |
| Пустая строка, только пробелы | Ошибка ввода |
| `2.5`, `12.0`, `12abc`, `1e3`, `0x10`, `Infinity` | Ошибка ввода |
| `9007199254740990` | Минимальный `2`, максимальный `9007199254740990` |
| `9007199254740991` | Чётных делителей нет |
| `9007199254740992`, `-9007199254740992` | Ошибка: число вне безопасного диапазона |

В браузере проверь успешный расчёт, отсутствие делителей, ошибку ввода, исправление ошибки, сброс устаревшего результата и отправку через Enter. Используй Playwright, если он подключён; иначе выполни ручную проверку и явно укажи её формат.

Перед завершением прочитай `package.json` и запусти применимые существующие команды проверки типов, тестов, линтинга и сборки. Ориентиры: `check`, `test`, `lint`, `build`; реальные имена и параметры определяй по проекту. Автоматические проверки запускай в завершающемся режиме, без watch.

Не утверждай, что проверки прошли, если они не запускались или завершились ошибкой. Для заблокированной проверки укажи причину.
